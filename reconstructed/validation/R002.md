## Implementation and Pseudocode

```text
Start button:
    ReleaseAll -> new Kernel(parsed selected AFF, current Godot tick origin)
    clear held inputs/feedback -> first Frame -> begin ordinary3-second preroll
Godot _Process:
    session.Frame(current Time.GetTicksMsec)
    core.Frame -> actual range/expiry/completion
    renderer/HUD read E, note flags, counters, health and cached GameResult
Godot _Input(key):
    resolve physical D/F/J/K, then logical key/Unicode fallback
    ignore echo/duplicate DOWN
    DOWN -> core.Down(current tick, pointer=lane, lane2..5)
    UP -> core.Up(pointer)
    do not insert or reorder a gameplay Frame inside input
Mouse:
    lane click -> same core interface, separate pointer100
Results -> Play again:
    fresh Kernel, Timeline, counters, notes, contacts and result state
```

Clock: one monotonic Godot tick source for both callback types. The core handles
preroll/startup compensation/E. Visual Y=`590-(noteTime-E)*0.18` is an engineering
mapping in1100x740 canvas units, reading E directly rather than integrating delta.
No independent animation-clock drift or audio synchronization is claimed. Focus
loss releases contacts and gameplay continues; pause/lifecycle reconstruction is
not implemented. Callback reception time is used; physical/OS timestamp latency
compensation is not claimed.035's distinct frame-versus-input paths remain intact.
