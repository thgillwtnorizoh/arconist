## What I found / architecture

E025's trace parent and child are different gameplay identities. Parsed Arc owns
an immutable child collection; each parsed ArcTap references that exact parent.
Runtime ArcState owns ArcTapState objects; every child references its runtime
parent and parsed child, and has independent ID/time/local geometry/current world
position/input target/consumed/missed/contact/outcome/resolution time. Children
are reached through indexed parent membership, not independently added to the
ground tap list. Trace parent records are empty, so N counts only child units.
The exact E025 fixture gives N1/end2500, no invented parent head/tail/checkpoints.

Ordinary false arcs preserve R007 behavior. New supported syntax is one strict-
interior child on positive-duration bounded linear s/none/true color0 parent.
Coordinates/duration/timing/extra bounds retain R007's validated domain. Bare
trace parents, children on false arcs, multi-child lists, curves, unsupported
modes/effects, timing changes inside parents and overlapping/linked/near parents
reject explicitly. Ground taps within240ms of a child or holds intersecting that
window reject as a conservative engineering domain, not a recovered native rule.
General ground/child candidate conflicts are not claimed.

```text
PARSE → Arc(trace=true, Children=[ArcTap(parent=this,time)])
INIT  → parent geometry → child local evaluator → runtime parent/child links
        N=taps+hold/ordinary-arc records+children; trace parent contributes zero
FRAME → authoritative E/ranges/parent depth → child current position
        → ordinary continuous processing (trace excluded)
        → parent child expiry if E>child.time+100 → existing recorder/results
DOWN  → fresh retained ID → refresh E only → traverse active parent children
        → arc-tap spatial flag1 → chronological supported candidates
        → shared tap-tier missed/consumed guard → classification → one recorder
UP/CANCEL → contact cleanup; MOVE/FRAME/resume never synthesize child DOWN
```

The accepted tap classifier is shared with ground notes; guards stay after
collection. A consumed child can remain spatially eligible and collected, then
reject through its own consumed guard. Pointer identity, geometry rejection and
cooldown are not substituted for this gate. Ground keys provide no sky contact.
