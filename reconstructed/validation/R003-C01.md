## Repair

On a fresh Ubuntu24.04 host with Godot4.7.2.stable.mono.official.ed1daf0bf and
SDK10.0.402/runtime10.0.13, default Godot export reproduced the reported
Publish/GetTargetFrameworks failure. It returned0 and left partial EXE/PCK without
runtime. Restore succeeded after supplying the host's missing official .NET
Standard2.1 targeting pack. The same silent Publish failure remained afterward.

Direct `dotnet publish -c ExportRelease -r win-x64 --self-contained true
-p:GodotTargetPlatform=windows -m:1 -nr:false` succeeded with zero warnings/errors.
With process-local DOTNET_PROCESSOR_COUNT=1, the actual Godot exporter also
completed Publish. Both build entry points now set this for child SDK processes.
The underlying concurrency failure is unresolved; the serialization workaround
is observed, not an inferred permanent fix to Godot or the SDK.

A secondary ERROR occurred when Godot tried packing a bridge/obj sourcelink JSON
that Publish removed after indexing. `.gdignore` files now prevent scanning the
bridge/tests folders. This does not remove their project references or source.
Fresh import/export then emitted no ERROR or WARNING lines.

No gameplay or shared-core change. Full build/package results, immutable source
identity, integrity and delivery evidence are appended after the final run.
