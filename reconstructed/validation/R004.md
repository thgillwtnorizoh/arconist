### Typed chart units

Hold start/end/integer raw lane remain typed; raw1..4 maps to internal2..5.
Interval at start uses f32(60000/BPM), divisor1 if BPM>=255 else2, then density.
Ordinary generator flag0 starts at index1, excludes the integer quotient upper
bound and truncates each f32(start+interval*i); empty records use the midpoint.
No independent head/tail units are invented. N=taps+record weights;
end=max(tap.time+120,hold.end+500). E026 and E010 density2 are independent oracles.
Hold endpoints use the preserved integer predepth/current float-add ordering;
index spans the original floating-depth endpoint buckets; admission uses minimum
current endpoint depth<300. Existing tap buckets/admission/expiry are preserved.

Supported hold domain: nonnegative time, duration>=2ms, raw integer1..4, end below
INT_MAX−1,000,000, finite interval>=1ms, <=100000 generation steps, distinct interior
integer record times and bounded bucket span. Explicit rejection of R001's1ms hold
specimen preserves that existing regression without editing its assertion. Other
fractional lanes, extreme/degenerate cases, special modes/groups/reverse expansion
are not silently accepted. Positive default timing changes retain their existing
depth behavior; hold interval is chosen once from the timing at its start.

### Runtime and input

Parsed Hold, HoldState, Latched, Holding, Contacts, activating identities,
CheckpointState.Resolved/Outcome/ResolvedAt and cached GameResult are separate.
DOWN refreshes E but never runs FRAME/range/expiry. Initial hold eligibility is
start<E+100 and E<end; latch writes stop initial iteration unconditionally.
Tap guards and all existing threshold/order behavior remain intact. Distinct-start
chronology is native-supported; source order is the existing engineering tie
break, not a claim about universal equal-start native priority.

Each frame resets activity, traverses all retained contacts and sets activity only
with latch, matching lane and start<E<end. Both contacts may sustain one hold;
neither owns it exclusively. UP removes the actual contact but leaves latch and
current-frame activity until a subsequent frame. A fresh DOWN generates a new
logical identity, including reuse of the same adapter pointer. MOVE only updates
retained lane; lane0 represents a desktop contact outside the supported track.
The mouse membership adapter is a bounded desktop implementation, not Android
transport/capacity/timestamp or physical multitouch equivalence.

### Records, health, score and results

Due cutoff is trunc(f32(E+interval/2)). The inactive routine first computes the
double half-cutoff/count, preserves the separate first-record flag condition, then
uses trunc(f32(E−min(2*interval,500))). Ordinary factory+6c remains0 in this domain;
other flag producers are outside scope. Both resolve backwards through the pending
prefix and stop at an already-resolved record. Each weight creates a distinct
recorder/clamp call. Accepted hold units are shining PURE; missed units cost2HP,
reset combo and do not recompute the stored score. Float32 gain stages and ordinary
score denominator/result LOST reconciliation remain shared with taps.

## Pseudocode

```text
parse typed tap/hold/timing -> generate ordinary interior records -> N/end/index
DOWN: update E -> chronological eligible candidates
    tap: existing guard/classifier; stop if consuming
    hold: latch=1; STOP even if already latched
FRAME: timeline -> endpoint depth/range -> clear hold activity
    each retained lane contact activates all eligible latched holds (start<E<end)
    active holds resolve due prefix; inactive holds resolve original overdue prefix
    each unresolved record -> unique outcome -> per-weight recorder/clamp
    ordinary completion -> cached results
UP: remove retained identity; preserve latch; no FRAME/time update
MOVE: update retained lane only; no initial tap arbitration
renderer/HUD: read core only -> result/restart -> fresh core/visual trees
```
